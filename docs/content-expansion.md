# Ёмкость каталога фактов — 1 октября 2026

Под «FAQ» здесь понимаются существующие карточки фактов: заголовок, короткий тезис и объяснение на русском и английском, плюс ID, тема и ссылка на первоисточник. Это оценка вместимости и редакционный план; новые факты в текущую сборку ещё не добавлены.

## Ограничение Яндекс Игр

[Пункт 1.21 требований](https://yandex.ru/dev/games/doc/ru/concepts/requirements) и [инструкция по загрузке](https://yandex.ru/dev/games/doc/ru/console/add-new-game) ограничивают **сумму размеров файлов игры до ZIP-сжатия 100 МБ**. Оба языка должны находиться в одном архиве. Проверка `scripts/check-build.mjs` теперь использует консервативный десятичный предел `100_000_000` байт.

После `npm run build:yandex` текущий `dist-yandex` содержит пять файлов:

| Файл | Размер |
| --- | ---: |
| JavaScript игры с каталогом ru/en | 256 690 байт |
| CSS | 35 248 байт |
| HTML, worker и favicon | 4 611 байт |
| **Всего до сжатия** | **296 549 байт (0,297 МБ)** |

Проверочный ZIP с обычным deflate занял 81 225 байт; для требования 1.21 важны **296 549 байт**, не размер ZIP. До десятичного лимита остаётся **99 703 451 байт**. Каталоги разработки, документация и галерея в Yandex-сборку не входят.

## Стоимость текстовой карточки

Для существующих 160 карточек измерены UTF-8 размеры сериализованных игровых данных и соответствующих английских записей: русский каталог — 90 003 байта, английский — 35 740 байт, вместе — 125 743 байта. Средняя пара ru/en занимает **786 байт**, 90-й процентиль — **863 байта**, максимум — **976 байт**. Это модель содержания одной карточки, а не точное изменение минифицированной сборки: сборщик может объединять повторяющиеся поля и добавлять служебные байты.

Для планирования удобно резервировать **1 КБ на новую двуязычную карточку** и пересчитывать реальный `dist-yandex` после каждой партии. При таком допущении только файловый предел допускает примерно **99 тысяч дополнительных карточек**. Это математическая оценка свободного места, не целевой размер каталога: она не учитывает скорость поиска, отрисовку коллекции, редактуру и проверку источников. Даже 10 тысяч новых карточек по этой модели увеличили бы сборку примерно до 10,3 МБ — намного ниже лимита.

| Новые карточки | Всего карточек | Оценка `dist-yandex` до сжатия |
| ---: | ---: | ---: |
| +160 | 320 | 0,46 МБ |
| +640 | 800 | 0,94 МБ |
| +10 000 | 10 160 | 10,30 МБ |

## Практический план

Первая партия — **+160 карточек**, по 20 в каждой из восьми тем: всего 320. Прогноз дополнительного веса — около 160 КБ при резерве 1 КБ на пару языков. Это разумный размер для проверки новых фактов, переводов и скорости коллекции на телефоне.

Следующая цель — **800 карточек всего**, то есть ещё +480 после первой партии и **+640 к текущему каталогу**: по 100 фактов в каждой теме. Консервативная оценка размера сборки при неизменном коде — около **0,94 МБ до сжатия**. Перед такой партией следует добавить постраничный вывод или виртуализацию коллекции и проверить поиск: сейчас открытые карточки выводятся все сразу. Рост текстового архива почти незначителен, а число элементов на экране и объём редакционной проверки увеличатся в пять раз.

Для первой партии подготовить по пять новых групп источников на тему и по четыре самостоятельных факта из каждой группы. Направления поиска: космос — объекты Солнечной системы и исследования NASA; природа — виды и среды обитания из зоопарков и океанических институтов; технологии — стандарты и повседневные технологии; искусство — музейные коллекции и техники; история — предметы и документы музейных и библиотечных собраний; география — природные объекты UNESCO и национальных служб; наука — физика, химия и науки о Земле; человек — органы чувств и физиология из NIH и профильных институтов. Конкретные факты добавлять только после проверки первоисточника, даты и формулировки на обоих языках.

Каждая новая запись должна получить стабильный ID, тему, прямой URL и дату проверки; ru/en должны сохранять одни и те же числа, оговорки и смысл. Перед выпуском проверить уникальность ID, отсутствие повторов, полноту двух языков, рендер коллекции и победы, поиск, обновление старого профиля, мобильное устройство и фактический размер Yandex-сборки. Сохранение хранит ID карточек, поэтому расширение каталога не должно менять уже выданные награды.
